### 1. Gemini 유료 → 무료 키 전환 (비용 월 ₩2.5만 → 0)

- 야간 자동화가 죽어 있었다: 선불 크레딧(7/20 충전 ₩16,000)이 **9일 만에 소진**, 잔액 -₩94 →
  전 모델 429 → 신규 86건이 검수 없이 pending에 방치.
- 지출 내역을 모델별로 보니 **`gemini-flash-latest` 별칭이 최신 고가 모델(Gemini 3.6 Flash)을
  가리키고 있었고** 그게 전체 지출의 93%. 요청당 약 ₩30.
- **결론: 유료는 애초에 필요 없었다.** 무료 티어로도 하루 수집량(80~130건)을 전부 소화한다.
  유료가 필요했던 건 카탈로그 재검수 주기를 45일→2주로 줄이는 것뿐이고, 그게 크레딧을 태운 주범.
- **결제 안 붙은 새 프로젝트로 키를 만들어 GitHub Secret `GEMINI_API_KEY`를 교체.**
  검증 실행: 재검수 250건 처리, 숨김 15 / 유지 235 / **실패 0, 429 없음**.
- 예산값을 무료 시절로 원복: `MAX_PER_RUN` 600→450, `AUDIT_PER_RUN` 250→60(주기 약 45일).
- 함정: 비용 아끼려 `gemini-2.0-flash-lite`를 고정했더니 **무료 티어 할당량이 아예 0**
  (`limit: 0`)이라 매 실행 실패 요청 하나만 낭비. 고정 제거함.

### 2. 관리자 승인 버그 3종 (사고의 원인)

세 개가 겹쳐서 "승인했는데 사라진다"로 보였다:

1. **"전체 선택" 버튼이 렌더 시점 목록을 클로저에 붙잡음** → 하나씩 승인해도 그 목록에는 남아
   있어서(화면에서만 카드가 사라짐), 이어서 "전체 선택 → 삭제"하면 **승인한 것까지 삭제**.
   → 클릭 시점에 `currentFiltered()`로 재계산하도록 수정.
2. **0행 수정을 성공으로 오해** → Supabase는 "대상 행 없음"을 에러로 안 준다. 이미 삭제된
   유령 카드를 승인하면 화면·배지만 올라가고 DB엔 아무 일도 없었음.
   → 승인 3경로 모두 `.select('video_id')`로 실제 수정 행을 받아 검증, 없으면 알림 + 목록에서 제거.
3. **대기 뷰 일괄 삭제가 승인된 항목까지 포함** → 확인창은 무심코 넘기게 되므로, 묻지 않고
   **대상에서 아예 제외**하도록 변경. 승인 시 삭제 선택에서도 자동 해제.

덤으로 **"선택 승인"(초록) 버튼** 추가 — 좋은 것만 체크해서 한 번에 승인 가능.

## 자주 헷갈렸던 것 / 재발 방지 메모

- **CSS/JS 파일을 고칠 때마다 `?v=YYYYMMDDx` 캐시 버전을 반드시 올려야 함** — 오늘 `i18n.js` 버전을
  안 올려서 새 번역 키가 브라우저에 안 보이는 사고가 한 번 있었음 (고침).
- Supabase 새 API 키 체계에서 **Direct connection = IPv6 기본, Session pooler = IPv4 가능**.
  GitHub Actions는 IPv4만 되므로 pooler 필수, 유저명도 `postgres.프로젝트참조` 형식이어야 함.
- `pg_dump`는 자기보다 **최신 버전 서버**를 거부함 — 서버 버전에 맞추거나 넉넉히 최신으로.
- GitHub Actions `if:` 조건절에서 `secrets.X` 컨텍스트 직접 참조가 파서 에러 남 — env로 받아서
  스크립트 안에서 체크해야 함.
- 방문자 IP/이메일 등 민감정보가 DB에 있으므로 **백업 파일은 절대 공개 저장소에 커밋 금지**.
  (2026-07-30에 `.gitignore`로 `db-backup.sql`을 막아뒀다 — 워크플로가 `git add -A`를 쓰게
  바뀌었으므로 단계 순서가 바뀌면 새어나갈 수 있었다.)
- **Supabase는 "대상 행 없음"을 에러로 주지 않는다.** `.update().eq()`가 0행을 고쳐도
  `error: null`이다. 관리자 조작은 `.select()`로 실제 수정 행을 받아 확인해야 한다.
- **PostgREST는 한 응답을 1000행에서 자른다.** `.limit(10000)`은 무시된다. 정렬 없이 쓰면
  어느 1000행이 올지도 보장되지 않는다(체류시간 조인이 이걸로 조용히 깨져 있었다).
  많이 가져와야 하면 `.order()` + `.range()`로 페이지네이션할 것.
- **모델 별칭(`-latest`)의 단가를 신뢰하지 말 것.** 별칭이 최신·고가 모델을 따라가면서
  비용이 조용히 수십 배가 됐다. 비용이 중요하면 명시적 모델을 고정하되, 그 모델이 해당
  티어에서 쓸 수 있는지 먼저 확인할 것(구형 모델은 무료 할당량이 0일 수 있다).
- **API 비용 추정은 며칠 뒤 결제 콘솔과 대조하는 것까지가 추정이다.** ₩16,000이 "1년 이상"
  간다고 추정했는데 9일 만에 끝났다(40배 오차). 사용량을 바꾸는 변경을 하면 추정도 갱신해야 한다.
  그리고 추정보다 **지출 한도(Spending limit)** 같은 구조적 방어가 낫다.
